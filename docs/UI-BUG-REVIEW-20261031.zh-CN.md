# UI 第二轮缺陷复查

日期：2026-10-31。重点复查“顶栏首次打开不完整，缩放后才恢复”以及“设置打开卡顿”。

## 定位与修复

| 问题 | 原因与修复 |
| --- | --- |
| 菜单首次显示依赖缩放 | MenuStrip 使用显式坐标，却仍启用 AutoSize。测试中宽度从指定的 1360px 缩到 295px；不同字体／布局阶段可能隐藏菜单项。关闭 AutoSize，统一在创建与主窗口布局时计算完整宽度和高度，验证无需先缩放便能显示四个菜单。 |
| 重建菜单残留旧实例 | 重建前移除并释放旧菜单，避免重复条目和事件；工作台已建立时不再由旧工具栏定位代码改写其位置。 |
| 设置首次打开耗时超过 8 秒 | 多层 AutoSize GroupBox、百分比 TableLayoutPanel 和内容绑定反复计算整个控件树。改为按可用宽度进行自上而下布局；绑定期间批量暂停布局，完成后统一恢复。 |
| 打开设置可能探测不可用路径并改写显示值 | 移除加载阶段的 Directory.Exists；仅在配置路径为空时使用默认位置，不因暂时离线、失联或不存在就把原路径替换为桌面。 |
| 未使用的账号页也重复克隆、绑定数据 | 账号数据延迟到首次选择账号页时加载，移除打开时的两次重建。未访问账号页便保存其他设置时，原账号集合保持不变。 |
| 账号控件关闭时空引用 | 关闭和保存均检查初始化状态，释放可重复调用；控件销毁也释放已有编辑副本。 |
| 空账号列表绘制和字体资源错误 | 不再 Dispose 系统传入的 e.Graphics；表头字体由控件持有并在销毁时释放，避免重复创建后遗失所有权。 |
| 设置搜索命中后仍看不到目标 | 选择标签页后调用 ScrollControlIntoView，定位到滚动区域下方的匹配分组。 |
| 凭据警告阻塞首次绘制 | 将原有警告延迟到设置窗体显示后，再以设置窗体为属主显示，避免在 Load 中阻塞未绘制的窗口。 |

## 验证结果

- Release 完整回归通过 **437 项断言**，包含真实设置加载处理及首次显示的计时与布局检查。
- 菜单首次显示检查在任何测试缩放之前执行；检查完整宽度、四项可见性、窄窗口及重复重建。
- 设置界面覆盖一般、连接、高级、预分享密钥和流媒体页，在 720 / 880 / 1080px 宽度下检查标签、输入框不重叠。
- 检查不可用目录不被替换、未打开账号页保存不改账号集合、按需初始化、重复清理、绘制结束后调用方画布仍可使用，以及搜索滚动定位。
- Debug / Release 构建通过，12 个 XML 文件解析通过，`git diff --check` 通过。

上一轮的绘制检查未覆盖真实设置加载耗时；本轮补上了这一缺口。测试不启动真实下载、不加载真实账号配置；真实多屏 DPI 切换和大规模真实配置仍需设备上的后续体验，不能据此声称所有 UI 缺陷均已消除。

运行入口保持为 `bin/Release-VisualRefresh/MegaDownloader.exe`。
