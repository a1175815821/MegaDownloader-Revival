# MegaDownloader UI 视觉排查

> 以下是改造前的审查记录。原生实现已完成，见 [视觉整理实施记录](UI-VISUAL-REFRESH.zh-CN.md)。

日期：2026-10-31。基于仓库 `ad2d304` 的当前源码，以及仓库中的 v2.6 主窗口深浅色、添加链接、预检、设置截图。

本轮为视觉审查与方向设计，没有修改应用源码，也没有启动实际下载程序。截图不等于当前运行实例的取证；字体回退、实际 DPI、悬停与焦点表现中未实测的部分会单独注明。

## 结论

界面缺少美感的主要原因是视觉规则没有形成完整系统：同权重的控件过多、中文排版缺少统一策略、分区靠大块底色与边框、主要内容被常驻辅助区挤压、新旧窗口风格断层。WinForms 的默认外观确实陈旧，但这些问题可以在现有技术栈内解决。

建议先完成一次统一的视觉整理：把字体、颜色、间距、按钮层级和状态表达收敛到少量公共组件，再改主窗口及添加流程。暂时没有必要为了这次审查直接重写 UI 框架。

## 发现与证据

### A. 中文字体、字号与窗口之间缺少共同基准〔优先〕

- 截图：主窗口中文正文偏细小，空态长句呈现明显的衬线／宋体式笔形；设置窗口整体更接近旧式系统字体。
- 源码：`Forms/Main.Designer.vb:535` 使用 `7,15` 的字体缩放基准及 Segoe UI 9pt；`Clases/UiStyles.vb:115` 同样固定 Segoe UI 9pt。`Forms/Configuration.Designer.vb:1250` 则仍用 `6,13` 基准，没有设置统一窗体字体，局部控件保留 Microsoft Sans Serif 8.25pt。
- 判断：可以确认字体策略不统一；仅凭 PNG 不能确认中文最终落到了哪一款回退字体，也不能把字形差异全部归因于字体。控件的 GDI / GDI+ 绘制路径也需要实测。
- 改进：按 UI 语言选择字体并检测安装情况。简体中文优先 Microsoft YaHei UI，缺失时尝试 Microsoft YaHei，再退回系统可用字体；繁体中文使用对应的 Microsoft JhengHei 系列，拉丁语种保持 Segoe UI。建议先试正文 10pt、说明 9pt、页面标题 15–16pt、分区标题 10–11pt，并以中文实际渲染结果校准。
- 实施注意：字体应在首次布局及自动缩放前确定。同步调整 AutoScaleDimensions 与布局测量，避免只把 Font 从 9 改为 10 导致控件裁剪。标题与正文的差异同时依靠字号、字重和间距。

### B. “弱按钮”实际仍然很重〔优先〕

- 截图：开始、暂停、停止、定时下载、设置、收起详情，以及左栏三个工具入口都带矩形边框，形成连续的框线噪声。
- 源码：`Clases/UiStyles.vb:91` 将 PrimaryButton 与 QuietButton 放在同一分支，非主按钮一律 `BorderSize = 1`；`Clases/ThemeManager.vb:738` 对普通 Button 同样统一加边框。`Forms/Main.vb:1698` 又给侧栏快捷按钮重复赋同类样式。
- 影响：添加链接虽然是红色主按钮，但其他操作数量和轮廓太强，视线很难按主次移动。QuietButton 的命名没有转化为实际的低强调外观。
- 改进：拆成 Primary、Secondary、Ghost、Danger 四种角色。添加链接使用唯一的实心强调按钮；取消、浏览等需要边界的操作保留轻描边；工具栏和侧栏命令默认无框，仅在悬停、按下及键盘焦点时提供清晰反馈；停止操作移到队列菜单或降低默认强调度，保留入口。

### C. 布局让辅助区域与任务列表争夺空间〔优先〕

- 源码：`Forms/Main.Workbench.vb:20` 默认 `detailsRequested = True`；`:251` 为详情保留至少 238 个逻辑像素，只按窗口宽度决定显示，不要求已有选中任务。
- 截图：空任务状态下，右侧仍显示“选择一个任务查看详情”，主列表却失去约一栏宽度；上方还常驻一个较大的“收起详情”按钮。
- 改进：空队列隐藏详情；未选任务时让列表优先用满宽度。选择任务后才按需打开详情，保留用户的显式开关偏好。宽窗口使用右栏，窄窗口使用底部详情或独立属性窗口，不必处处维持三栏。
- 侧栏只承担导航和必要工具，速度等概览可放在底部或紧凑状态条。留白用于分组，不需要为了填满侧栏不断增加入口。

### D. 有留白，但缺少稳定的内边距和对齐线〔优先〕

- 源码：`Forms/Main.Workbench.vb:240` 起为面板之间设置 12px 间隔，但页面标题从面板 x=0 开始；搜索标题单独占最多 112px；表头另有自己的缩进。外部沟槽与内部内容起点不是同一套规则。
- 截图：标题贴着列表左边界，搜索输入又向右缩一大段；计数远离标题；侧栏内容较密，主要区域却空旷。
- 改进：建立 4/8/12/16/24/32 的逻辑间距表。页面内容边距 24、同组间距 8、区块之间 24。标题、说明、工具栏、列表首列共享内容对齐线；任务包计数贴近标题；搜索改为工具栏内的组合输入框，保留 AccessibleName。
- 全部尺寸在统一的 DPI 转换入口处理，文字高度采用实际测量兜底。不要分别在各窗体里复制比例公式与数字。

### E. 列表过于“表格化”，重要信息反而被挤压〔优先〕

- 源码：`Forms/Main.vb:415` 每次启动强制恢复百分比数字列；`:1126` 单独绘制两位小数百分比，与进度条列并列。`:1196` 的 FormatRow 将完成／失败项整行文字变成绿色／红色。
- 影响：百分比与条形进度占两个表头；姓名、大小、状态、速度、时间与重复进度一起争宽。整行语义色使文件名、大小等普通信息也带上成功或错误强调。
- 改进：默认列收敛为名称、大小、状态、进度、速度、剩余时间。百分比与细进度条合并在一个 renderer 内，数字优先显示整数或一位小数；高级用户继续通过列菜单展开其他信息，保留已有列配置的兼容和迁移策略。
- 文件名保持正文色，状态通过小图标＋文字或轻量徽标表达，颜色只落到状态和必要的进度反馈。使用轻横向分隔或非常淡的交替底色；避免大面积彩色行、深边框和竖网格。初步建议常规行高 40–44 个逻辑像素，紧凑模式 32–36；展开子项可保持紧凑，避免大队列行数骤降。
- 大数据路径继续复用 TreeListView / 虚拟列表。视觉调整不应改成每文件一个 Panel 或卡片。

### F. 浅色像蓝灰拼块，深色像整体换了背景色〔优先〕

- 源码：`Clases/ThemeManager.vb:34` 起，Canvas、ControlBack、ButtonBack、ButtonBorder 主要在偏蓝灰的相邻颜色之间变化。`Forms/Main.Workbench.vb:119` 又把标题、侧栏、详情和工具栏统一登记为 Surface。
- 截图：浅色界面的蓝灰沟槽分割出几块白面板；深色版本主内容、侧栏、详情的明度接近，却保留很强的按钮边界及原生 GroupBox 轮廓。
- 改进：明确“应用底层、导航层、内容层、浮层”四种表面角色，而不是按控件类型平均染色。降低大面积冷蓝色，用中性底色与少量分隔线；主要文字、辅助文字、强调与状态各有独立语义。
- 保留 MEGA 红作为主要操作／品牌强调色，选中导航使用同源淡红背景。红色错误通过警告图形和文案与品牌操作区分；链接蓝用于链接，下载中蓝／完成绿用于局部状态。不要把分区标题也全部染成链接色。
- 深色主题单独校准层级、边框和禁用状态，不用简单反色。可读性先于降低对比度；移除次要边框时保留明确的焦点轮廓和输入边界。

### G. 空态把一句说明放得很大，却没有明确的行动层级〔次优先〕

- 截图：列表中央是一整句大字，宽度不足时在句末突兀换行；右栏同时重复提示添加或选择任务。
- 源码：`Forms/Main.Workbench.vb:228` 复用列表 EmptyListMsg；`Clases/ThemeManager.vb:622` 只更新 EmptyListMsgOverlay 颜色，没有建立空态专用字级和内容宽度。
- 改进：拆成小图标、短标题“从一个链接开始”、两行以内的辅助说明及一个轻量“添加链接”入口。限定说明宽度，避免随着列表宽度拉成长横幅。已有筛选结果为空时使用“没有匹配的任务”，不要复用无任务文案。

### H. 新主窗口、添加流程、预检、设置还没有成为一个产品〔次优先〕

- 详情：`Forms/Main.Designer.vb:158` 起仍以 GroupBox 承载详情；将 FlatStyle 设为 Flat 并不等于获得完整可控的现代边框。
- 添加：`Forms/AddLinks.Layout.vb:36` 固定输入区 160px，下面有至少 36px 的计数区、选项 GroupBox 及滚动容器；截图中输入与选项之间留有一段缺少分组意义的空隙。
- 预检：`Forms/BatchPreflightView.vb:522` 明确使用 FixedSingle 外框。截图上方的总计、进度、筛选、批量工具和键盘说明连续堆叠，轻重接近。
- 设置：`Forms/Configuration.Designer.vb:1250` 起使用旧字体缩放基准及固定尺寸窗口，传统 TabControl + 多层 GroupBox 与新工作台断层明显。
- 改进：详情采用 Panel＋标题＋单条轻分隔；添加页把“保存位置／包名／高级选项”分组，密码和自动解压等进阶设置按需展开；预检保留进度、筛选、列表、确认四层，帮助说明降级为辅助文本；设置改为统一字体与内容布局，按下载、连接、外观、其他功能分组，不必为了视觉统一立刻替换所有原生输入控件。

### I. 字体与 DPI 的视觉验证仍需补上〔验证项〕

- `app.config:24` 将 `DpiAwareness` 写成 ApplicationConfigurationSection 的属性；微软 .NET Framework 文档展示的是段内 `<add key="DpiAwareness" value="PerMonitorV2" />`，项目 manifest 也同时声明了 DPI 感知。
- 这是一项需要单独核验的配置差异。不能凭配置文本断言应用已按预期缩放，也不能据此认定截图问题都是 DPI 所致。
- 下一轮实现时核对实际进程 DPI 感知、字体自动缩放和手工 DeviceDpi 缩放是否重复，并在 100%、125%、150%、200% 与跨屏移动下观察。

## 建议的第一套视觉规格

以下为设计起点，需要在原生控件中视觉校准，不是已实现或已验收的参数。

| 项目 | 浅色 | 深色／行为 |
| --- | --- | --- |
| 内容背景 | `#FFFFFF` | `#20252D` |
| 导航背景 | `#F7F8FA` | `#1A1F26` |
| 应用底层 | `#F1F3F6` | `#15191F` |
| 主文字 | `#232934` | `#E7EBF1` |
| 辅助文字 | `#657184` | `#A4AFBF` |
| 轻分隔 | `#E5E8ED` | `#343C48` |
| 品牌／主操作 | `#C73548` 配白字 | `#E45C6C` 配深字，分别校准对比度 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 | 逻辑尺寸统一换算 DPI |
| 按钮 | 高 34–36，左右内边距 12–16 | 主操作实心，普通命令无框 |
| 圆角 | 输入框和按钮 4–6 | 少量使用，不给每个布局分区套卡片 |
| 进度条 | 高 4–6，无外描边 | 选中、异常、完成状态可辨识 |

## 实施顺序

1. **公共样式**：扩展 UiStyles 的字体、间距和按钮角色；ThemeManager 改为优先尊重语义角色，减少各窗体换肤后的重复覆盖。统一图标规格和焦点／禁用反馈。
2. **主窗口**：重排标题＋操作＋搜索；按需详情；合并进度表达；弱化侧栏工具；重做空态。这一轮最直接改善每天看到的界面。
3. **高频弹窗**：添加链接和预检使用同一套排版、输入与确认规则，再整理设置与属性窗口。
4. **原生验证**：深浅主题、长中文／英文名、无任务／进行中／失败／大量任务、键盘焦点、窗口缩放及多种 DPI。已有回归覆盖按钮颜色完全相同的断言（`Tests/RegressionTests.cs:611`）应改为验证对应角色的预期值，不能让旧外观断言限制设计调整。

优先保留现有 WinForms + .NET Framework 4.8 + TreeListView。对按钮、搜索框外壳、导航与进度等高频部分编写少量统一自绘／组合控件即可开始；文字输入、焦点、键盘及辅助功能尽量沿用原生控件。原生标题栏可以先保留，不需要以无边框窗体作为现代化的前提。

若后续仍有复杂动效、丰富模板或系统材质等明确需求，再独立评估 UI 框架迁移。迁移应由产品需求决定，不能代替这次信息层级和排版整理。

## 示意方案与验证边界

对话中的示意提供“侧栏工作台”和“紧凑任务台”两个方向，使用示例任务；可搜索、切换任务状态、选择任务查看详情、暂停示意队列及查看设置。外观与密度可通过设计选项调整，也可查看无任务状态。

示意用于确认布局与视觉方向，并非 WinForms 的实际运行截图。示意使用 Noto Sans SC 展示中文无衬线排版；实际应用的字体仍需按 Windows 版本和已安装字体选择。浏览器字体抗锯齿、原生控件边界、DPI、滚动条与性能仍需在后续原生实现中校准。本轮没有运行应用回归或真实下载，也没有改动真实配置和下载队列。

示意已在 1024、736、320px 三种预览宽度下检查两种布局的浅／深色，共 12 个组合，无横向溢出；搜索、状态筛选、任务选择及详情、暂停、外观切换、添加示意和空态交互检查通过，浏览器未报告脚本错误。这些检查只验证示意，不替代原生 UI 验收。
